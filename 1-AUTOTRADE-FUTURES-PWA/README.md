این نسخه برای **Bybit V5 public market data** ساخته شده است:

- حالت پیش‌فرض: `BYBIT LIVE`
- endpointهای بازار: `v5/market/tickers` و `v5/market/kline` با `category=linear`
- کندل در حال تشکیل به‌صورت پیش‌فرض از امتیازدهی حذف می‌شود تا validation روی کندل بسته‌شده انجام شود.
- در خطای شبکه/محدودیت منطقه‌ای، قیمت قدیمی یا مصنوعی جایگزین نمی‌شود؛ نماد `DATA ERROR` نشان می‌دهد و سفارش Paper جدید ساخته نمی‌شود.

## فیچرهای v2.1

### ۱) فیلتر تاییدیه هم‌جهتی کندل‌های ریز (Micro-Candle Momentum Filter)

قبل از ورود، N کندل متوالی **بسته‌شده** تایم‌فریم ریز بررسی می‌شود؛ اگر همه صعودی باشند وزن داینامیک فقط به امتیاز خرید اضافه می‌شود (و برعکس برای فروش). Doji استریک را می‌شکند و اگر دیتای ریز‌کندل در دسترس نباشد فیلتر **خنثی** می‌ماند (نه مثبت، نه منفی). نتیجه روی کارت ارز با تگی مثل `3×1m ↑` نمایش داده می‌شود.

پارامترها (Settings → فیلتر کندل‌های ریز):

| پارامتر | پیش‌فرض | توضیح |
|---|---|---|
| `microCandleCheck` | `true` | روشن/خاموش فیلتر |
| `microCandleCount` | `3` | تعداد کندل متوالی (۲ تا ۴) |
| `microCandleTf` | `1` | تایم‌فریم ریز (1m یا 3m) |
| `microCandleBoostPct` | `15` | وزن درصدی هنگام تایید هم‌جهتی |

مسیر دریافت ریز‌کندل همان زنجیره ضدتحریم اصلی است (پروکسی Bybit → OKX مستقیم → Binance مستقیم) با کش ۱۵ ثانیه‌ای؛ اگر تایم‌فریم ریز با تایم‌فریم اصلی برابر باشد، بدون درخواست اضافه از همان کندل‌ها استفاده می‌شود. وزن داینامیک روی هر دو مسیر (موتور اجماع و فرمول‌ساز سفارشی) اعمال می‌شود.

### ۲) هشدار صوتی زنده (Web Audio API — بدون فایل خارجی)

- **سطح ۱ (Pre-Alert):** چایم ملایم وقتی امتیاز نماد از آستانه (پیش‌فرض ۷۵) عبور کند؛ با Cooldown مستقل برای هر نماد.
- **سطح ۲ (Execution):** دو بوق صعودی برای باز شدن خودکار خرید و دو بوق نزولی برای فروش.

پارامترها: `audioAlerts` (روشن/خاموش)، `preAlertScore` (آستانه)، `preAlertCooldownSec` (فاصله تکرار هر نماد)، `audioVolume` (۰ تا ۱). دکمه 🔊 در تولبار داشبورد و دکمه «تست صدا» در Settings موجود است. طبق سیاست مرورگرها صدا با اولین کلیک/لمس روی صفحه فعال می‌شود.

### ۳) علت شفاف باز نشدن معامله (Block Reason)

روی کارت هر ارز، دلیل دقیق رد شدن ورود خودکار نمایش داده می‌شود؛ مثلاً:

- «امتیاز ۷۸ کمتر از حد نصاب ۸۲ است (تایم‌فریم 60m)»
- «سقف ۳ پوزیشن همزمان پر است (۳ پوزیشن باز)»
- «Cooldown فعال: ۴۲ ثانیه دیگر برای BTCUSDT»
- «سقف ضرر روزانه ۳٪ پر شده؛ ورود جدید تا فردا مسدود است»
- «اتوترید مجازی (Paper Auto) خاموش است»

### ۴) لاگ ساختاریافته و خروجی JSONL

هر رخداد به صورت `{ t, level, msg, obj }` ذخیره می‌شود و با دکمه «📥 دانلود لاگ JSONL» در تب لاگ‌ها، فایل `trading_logs_[account]_[time].jsonl` برای کالبدشکافی آفلاین (مثلاً با `tools/manage_trades.py`) دانلود می‌شود.

### ۵) رفع باگ ترتیب کندل Binance

در نسخه‌های قبل، کندل‌های مسیر مستقیم Binance به‌اشتباه reverse می‌شدند و `candles.at(-1)` قدیمی‌ترین کندل را نشان می‌داد؛ این باگ رفع شد (Binance از قدیمی به جدید می‌فرستد و دیگر reverse نمی‌شود).

### ۶) رادار پمپ/دامپ و ارزهای تازه‌لیست (Pump/Dump Radar)

موتور کشف خودکار فرصت‌های بازار: کل صدها جفت‌ارز در «یک فراخوان» (Bybit tickers-all → Binance direct → OKX direct) پایش می‌شود و تغییر پنجره‌ای قیمت (پیش‌فرض ۶۰ دقیقه) از تاریخچه نقطه‌ای خودِ رادار محاسبه می‌شود.

- 🚀 **PUMP** — تغییر پنجره ≥ `pumpThresholdPct` (پیش‌فرض +۱۰٪) با گردش کافی → نماد خودکار به لیست اسکن موتور اصلی می‌پیوندد (کاندید خرید)
- 💀 **DUMP** — تغییر پنجره ≤ `dumpThresholdPct` (پیش‌فرض −۱۰٪) → کاندید فروش
- 🆕 **NEW** — تازه‌لیست‌ها (اولین بار دیده می‌شوند) به‌صورت WATCH زیر نظر می‌روند
- بوق مخصوص سه‌نُتی صعودی/نزولی برای PUMP/DUMP و چایم برای NEW
- در گرم‌سازی اولیه (تا تکمیل پنجره) با `pumpWarmupFallback` از تغییر ۲۴ساعته صرافی به‌عنوان تقریب استفاده می‌شود تا پامپ‌های تازه (مثل ۷۸٪ MOVE در یک ساعت) از دست نروند.
- فیلترهای امنیتی: حداقل گردش ۲۴ساعته (`pumpMinTurnover24h`)، سقف نماد همزمان (`pumpMaxSymbols`)، TTL خروج (`pumpTtlMin`)، ضد افزودن مجدد پس از سرد شدن، لیست سیاه استیبل‌کوین‌ها و حذف خودکار توکن‌های اهرمی (UP/DOWN/3L/3S/BULL/BEAR).

**نکته معماری مهم:** این ماژول فقط «کشف» می‌کند. تصمیم ورود/خروج همچنان با موتور استراتژی و همه گیت‌های امنیتی (حد ضرر روزانه، سقف پوزیشن، Cooldown، تاییدیه ریز‌کندل و گیت `I ACCEPT RISK` برای Real) است — هیچ مسیر میان‌بُری وجود ندارد.

| پارامتر | پیش‌فرض | توضیح |
|---|---|---|
| `pumpRadarEnabled` | `true` | روشن/خاموش رادار |
| `pumpWindowMin` | `60` | پنجره تشخیص (دقیقه) |
| `pumpThresholdPct` | `10` | آستانه پمپ (٪ مثبت) |
| `dumpThresholdPct` | `-10` | آستانه دامپ (٪ منفی) |
| `pumpMinTurnover24h` | `10000000` | حداقل گردش ۲۴ساعته دلاری |
| `pumpMaxSymbols` | `5` | سقف نماد کشف‌شده همزمان |
| `pumpTtlMin` | `120` | ماندگاری نماد کشف‌شده (دقیقه) |
| `pumpPollSec` | `30` | فاصله پول رادار (ثانیه) |
| `pumpNewListingAlert` | `true` | هشدار تازه‌لیست‌ها |
| `pumpNewListingMin` | `720` | سن «تازه‌لیست» (دقیقه) |
| `pumpWarmupFallback` | `true` | تقریب ۲۴ساعته در گرم‌سازی |
| `pumpBlacklist` | استیبل‌ها | لیست سیاه با کاما |

## Paper Trading

Paper به‌صورت پیش‌فرض فعال است و این موارد را ثبت می‌کند:

- fee ورود و fee خروج به‌صورت جداگانه
- round-trip fee تخمینی روی کارت سیگنال
- اسلیپیج ورودی
- gross PnL و net PnL بعد از هر دو fee
- win-rate فقط بر مبنای معاملات بسته‌شده و Net PnL
- Profit Factor، Expectancy، Max Drawdown و میانگین زمان نگهداری
- stop loss، take profit، حداکثر زمان نگهداری و daily loss limit

Fee پیش‌فرض قابل تغییر است؛ مقدار واقعی Taker fee حساب/سطح VIP خودت را در Settings وارد کن. Funding، latency و تفاوت اجرای Backend هنوز در این آزمایشگاه مدل نشده‌اند.

## Real Trading

- `Real` همیشه با `OFF` شروع می‌شود.
- فعال‌سازی به عبارت `I ACCEPT RISK` نیاز دارد.
- داده Mock اجازه ارسال واقعی ندارد.
- مقصد payload از Settings قابل انتخاب است: `lbank-futures` یا `bitunix-futures`.
- مسیر داخلی `/api/lbank/order` فقط `DRY_RUN_ONLY` است.
- برای سفارش واقعی باید `realWebhookUrl` را به Backend امن خودت بدهی؛ API Key/Secret و منطق امضای LBank/Bitunix باید فقط روی Backend بماند و Withdraw خاموش باشد.
- PWA مستقیماً به کیف پول یا API Secret وصل نمی‌شود؛ Backend امن تو محل اتصال به حساب خودت است.

در داشبورد، جدول `ورودی دیتای بازار` منبع، قیمت Ticker، زمان آخرین کندل بسته، تعداد کندل و سن داده را نشان می‌دهد؛ نمودار هم با انتخاب نماد تغییر می‌کند و JSON ورودی Parse‌شده را نمایش می‌دهد.

سه پروفایل ریسک `low / medium / high` برای مقایسه نتیجه‌ها وجود دارد. هر معامله با پروفایل خودش tag می‌شود و گزارش روی پروفایل انتخابی فیلتر می‌شود؛ بنابراین می‌توانی Low را چند روز، سپس Medium و High را جداگانه مقایسه کنی. گزارش Paper شامل Win-rate، Net PnL، Fees، Profit Factor، Expectancy و Max Drawdown است.

کلاس‌های اصلی در `src/js` ماژولار و مستقل هستند: `MarketClient`، `MomentumScalpStrategy`، `PaperBroker`، `PerformanceReport`، `PriceChart`، `RealBroker`، `SettingsStore` و `DashboardView`.
