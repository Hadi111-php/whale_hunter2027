## §۱ تحلیل `Hyper.txt` — سیستم مانیتورینگ نهنگ آن‌چین (۱۶۴۲ خط)

**چیست:** دو نسخهٔ پایتون (ساده + حرفه‌ای) برای رصد جریان پول نهنگ‌ها به/از کیف‌پول‌های صرافی‌ها با Etherscan API + SQLite + داشبورد Rich/SocketIO.

### ایده‌های درست و ارزشمند ✅

| ایده | چرا طلاست |
|---|---|
| **جریان صرافی (Flow):** ورود بزرگ به صرافی = احتمال فروش (DUMP)؛ خروج بزرگ = انباشت (PUMP) | استانداردِ تحلیل آن‌چین — به‌جای رصد ۲۰۰ آدرس مبهم، کیف‌پول‌های شناخته‌شدهٔ صرافی رصد می‌شوند |
| **الگوی «نوک‌زدن مادر نهنگ»:** ≥۵ تراکنش کوچک در ۳۰ ثانیه از یک آدرس = تست بازار قبل از ورود بزرگ | مفهوم قابل‌تعمیم: رصد «آزمودن بازار» قبل از حرکت اصلی |
| **طبقه‌بندی نهنگ:** NORMAL 🐟 / LARGE 🐋 / MEGA 🔥 / MOTHER 👑 | لایه‌بندی اندازهٔ بازیگر |
| **⭐ حلقهٔ اعتبارسنجی:** هر سیگنال PENDING ثبت و بعد از ۱۰-۱۵ دقیقه با قیمت واقعی CORRECT/INCORRECT می‌شود → «درصد دقت واقعی» سیستم | **دقیقاً فلسفهٔ نردبان خودمان!** سیستم خودش مدام صادقانه قضاوت می‌شود |
| داشبورد زنده + آمار دقت | نظارت مستمر |

### محدودیت‌ها ⚠️

- نیاز به **Etherscan API Key** (رایگان: ۵ درخواست/ثانیه) — فعلاً نداریم.
- فقط شبکهٔ اتریوم (ERC-20) — نه Tron/سایر شبکه‌ها.
- کیف‌پول‌های OKX/Binance هاردکد شده‌اند و ممکن است کهنه باشند.
- آدرس‌های Hyperliquid لایه-۲ آربیتروم‌اند و مستقیماً روی OKX قابل ردیابی نیستند (خود فایل صادقانه توضیح داده).

## §۲ تحلیل `دیپسیک تحلیل نهنگها.txt` — سیستم امتیازدهی وزنی ضد‌نهنگ (۸۶۱ خط)

**چیست:** فلسفه + ماژول‌های پایتون برای امتیازدهی سه‌بخشی سیگنال‌ها.

### ایده‌های درست و ارزشمند ✅

| ایده | چرا طلاست |
|---|---|
| **فلسفهٔ وزنی:** عرفی ۳۰٪ ×۱.۰ / غیرعرف ۴۰٪ ×۱.۲ / نهنگ ۳۰٪ ×۱.۵ — «قوانین عرفی برای ریتیل نوشته شده‌اند و نهنگ‌ها از آن‌ها علیه ریتیل استفاده می‌کنند» | تغییر پارادایم: سیگنال‌های معروف را کم‌وزن کن |
| **فاکتورهای غیرعرف:** CVD هم‌جهت قیمت، هم‌جهتی اسپات/فیوچرز، سوییپ لیکوییدیتی، شتاب تعداد تریدها، بیدارشدن کیف خواب، خروج پول از صرافی (انباشت)، نبود اسپوفینگ، حرکت در ساعات کم‌لیکوییدیتی | لایهٔ دوم حقیقت‌سنجی |
| **ماتریس مادر/فرزند/نوه:** «مادر می‌خرد، فرزند و نوه می‌فروشند = بهترین فرصت خرید (انباشت مادر)» | سلسله‌مراتب بازیگران |
| **نشانه‌های تله:** رشد بدون خبر، نقدینگی زیر ۱۰K، واش‌تریدینگ (حجم ۲۴س غیرواقعی نسبت به نقدینگی)، تبلیغ همزمان KOLها | فیلتر ضد-پامپ‌قماری |
| مدیریت پوزیشن: ورود پله‌ای، TP اول +۵٪ برای ۴۰٪، تریلینگ زیر EMA20/سوئینگ، کول‌داون ۵-۱۵ دقیقه | منطق پخته |
| آستانه‌ها: ≥۷۵ ورود، ۶۰-۷۴ رصد، <۶۰ رد | همان ساختار امتیاز ما |

### اشکالات/ابهام‌ها ⚠️

- بخش نهنگ (مادر/فرزند/نوه) به دیتای آن‌چین نیاز دارد که **در کد موجود نیست** (WhaleActivity فرضی است) — بدون منبع دادهٔ واقعی عملاً stub است.
- وزن‌ها تجربی‌اند و اعتبارسنجی آماری نشده‌اند.

## §۳ چه چیزهایی همین الان ادغام شد (v2.9) — بدون API key، با دیتای واقعی

### ۱) ⭐ اعتبارسنج سیگنال/رادار (از Hyper.txt — تاج هر دو فایل)

- **futures-pwa:** هر سیگنال ≥۶۰ امتیاز (یک بار در هر ۳۰ دقیقه به‌ازای هر نماد) ثبت می‌شود؛ بعد از **۱۵ دقیقه** با قیمت واقعی قضاوت (حرکت ≥۱.۵٪ در جهت سیگنال = CORRECT). سلول جدید داشبورد: **«دقت سیگنال ۱۵m 🐋»**.
- **pump-dump-lab:** هر رویداد PUMP/DUMP با قیمت لحظهٔ رخداد ثبت و بعد از **۱۰ دقیقه** با کندل ۵ دقیقه‌ای واقعی قضاوت می‌شود. کارت جدید **«دقت رادار (۱۰m)»** + ستون **«نتیجه ۱۰m»** در جدول رویدادها (✅ درست / ❌ غلط + درصد حرکت).
- از این به بعد «دقت واقعی» سیستم‌ها همیشه جلوی چشم است — همان نظارت نردبانی، این‌بار روی سیگنال زنده.

### ۲) 🐋 تحلیل جریان ضد‌نهنگ (از دیپسیک §۴) — از دیتای موجود، رایگان

کندل‌های **Binance** (در نردبان مسیر v2.8) دو فیلد اضافه دارند که حالا پارس می‌شوند: تعداد تریدها و حجم خریدِ تیکری. از آن‌ها سه فاکتور «غیرعرف» محاسبه می‌شود:

| فاکتور | معنا | خروجی |
|---|---|---|
| `buyRatio` | سهم خرید تیکری از حجم (۰.۵=تعادل) | ~۰.۶+ = فشار خرید واقعی |
| `cvdDelta` | ΔCVD پنجره = خرید تیکری − فروش تیکری | مثبت = هم‌جهتی با رشد |
| `tradeAccel` | شتاب تعداد تریدها (کندل آخر ÷ میانگین) | >۱ = جهش فعالیت (از فاکتورهای دیپسیک) |

- روی کارت سیگنال: chip «جریان: ۶۸٪ خرید تیکری، CVD مثبت (خرید — ضد‌نهنگ) ✓هم‌جهت».
- **سه متغیر جدید در فرمول‌ساز:** `buyRatio`, `cvdDelta`, `tradeAccel` — می‌توانی در فرمول سفارشی استفاده کنی (مثلاً `buyRatio > 0.6 && cvdDelta > 0`).
- اگر منبع دیتا Bybit/OKX باشد (بدون فیلد تیکری)، صادقانه `available=false` — **هیچ دادهٔ ساختگی ساخته نمی‌شود** (Zero Fake Data).
- **تصمیم آگاهانه:** امتیاز کل سیگنال دست‌نخورده ماند (کالیبراسیون/بک‌تست‌های قبلی خراب نشود) — جریان به‌عنوان دادهٔ شفاف + متغیر فرمول، نه تغییر خودکار وزن.

### ۳) ایده‌های به‌عنوان «قانون عملی» که از قبل در سیستم بودیم

ATR استاپ (×۱.۵-۳ configurable ✓)، کول‌داون هر نماد ✓، سقف پوزیشن همزمان ✓، سقف ضرر روزانه ✓، MaxHold ✓ — تأیید شد که جهت درست بوده.

## §۴ چیزهایی که فعلاً ادغام نشد و چرا (نقشهٔ آینده)

| ایده | مانع | مسیر فعال‌سازی |
|---|---|---|
| رصد آن‌چین جریان صرافی (Hyper.txt کامل) | نیاز به Etherscan API Key | داداش یک کلید رایگان از etherscan.io بگیرد → ماژول `whale-flow` در pump-dump-lab (همان معماری: poll → event → اعتبارسنج — زیرساختش الان با validator آماده است) |
| سلسله‌مراتب مادر/فرزند/نوه | دیتای آن‌چین (Nansen/Arkham پولی است) | با Etherscan همان می‌شود «نهنگ‌های بزرگ واقعی» را لایه‌بندی کرد (MEGA ≥۵۰۰K$ / LARGE ≥۵۰K$ از فایل) |
| CVD دقیق ترید-به-ترید / Orderbook / Spoofing | WebSocket + endpointهای جدید | فاز بعدی: `publicRecentTrades` در پروکسی سرور |
| TP پله‌ای (+۵٪ برای ۴۰٪ پوزیشن) | تغییر ساختار پوزیشن | پروپوزال بعدی با ممیزی مرحله‌ای (اول سنجش اثرش با peakPnl/givebackPct موجود) |
