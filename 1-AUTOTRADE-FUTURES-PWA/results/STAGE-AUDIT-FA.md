## §۰ روش — نردبان ۸ پله‌ای (Stage Ladder)

ابزار جدید `tools/stage-audit.mjs` (بدون هیچ کپی موتور) همان `MomentumScalpStrategy` و همان `PaperBroker` زنده را کندل‌به‌کندل روی دیتای واقعی اجرا می‌کند و فقط با **override تنظیمات + فیلتر دلخواه روی «دلیل بستن»** لایه‌ها را روشن/خاموش می‌کند. برای هر معامله، MFE/MAE (بیشترین حرکت موافق/مخالف) هم رهگیری می‌شود.

| پله | چی اضافه می‌شود | خروجی‌های مجاز |
|---|---|---|
| R0 | هیچ — لبهٔ خام ورود | فقط TREND_FLIP + پایان داده |
| R0f | همان R0 ولی **بدون کارمزد** | سنجش هزینهٔ فرآیند |
| R1 | استاپ سخت ATR (۲.۲×) | + SL_HARD_STOP |

**نکتهٔ مهم روش:** پله‌ها مستقل نیستند — با بسته‌شدن زودتر پوزیشن، جای ورود بعدی آزاد می‌شود و تعداد معاملات بین پله‌ها فرق می‌کند. این «رفتار واقعی سیستم» است، نه خطای روش.

## §۵ فیکس v2.5 — بریک‌ایون بالغ (`breakevenMinAtr`)

**تغییر:** انتقال استاپ به نقطهٔ ورود فقط وقتی مجاز است که حرکتِ موافق به `breakevenMinAtr × ATR` رسیده باشد (پیش‌فرض ×1). سود اول نفس می‌کشد، بعد محافظت می‌شود.

- پارامتر جدید در تنظیمات: **«بریک‌ایون بعد از ×ATR»** (۰ = همان رفتار قدیم).
- بدون ATR هم‌تایم (ناهم‌ترازی TF)، گیت کنار می‌رود تا حفاظت قیمتی v2.4 دست‌نخورده بماند.
- ترلینگ و MaxHold به‌عنوان **پارامتر** باقی‌ماندند (تغییر پیش‌فرض ندادیم — چون اثرشان وابسته به TF است)، ولی دستور پخت TFهای چندساعته در §۶ آمده.
- تست‌های اثباتی گروه ۱۳ (۷ تست): سود نابالغ → استاپ ثابت؛ سود بالغ → انتقال؛ =۰ → رفتار قدیم؛ ناهم‌ترازی → حفظ حفاظت؛ SHORT؛ پیش‌فرض config؛ فیلد UI. **جمع: ۹۶/۹۶ سبز.**

## §۹ نردبان داده (v2.6) — ذخیره‌سازی هم نردبانی شد

خواستهٔ داداش هادی: «ذخیرهٔ لاگ و JSON ها هم باید نردبانی باشد تا از روی وقایع، سیستم را بهینه کنیم.» از این نسخه، خودِ سیستمِ زنده هم مثل ممیزی، برای هر معامله ثبت می‌کند که **هر پله در هر لحظه چه تصمیمی گرفت**:

### سه سطح ذخیره (Data Ladder)

| سطح | چیست | کجا |
|---|---|---|
| ۰ — خام | هر رخداد زنده (سیگنال، باز/بست، گارد) | لاگ JSONL (دکمهٔ «⬇️ لاگ JSONL») |
| ۱ — نردبان معامله | رکورد پله‌به‌پلهٔ تصمیم‌ها + خلاصهٔ `ladder` | داخل هر معامله در state و خروجی JSON |
| ۲ — خلاصهٔ لایه‌ها | `ladderRollup`: جدول «هر لایه چند بار بست و چند داد» + خوشهٔ ماهانه + ضریب برداشت | فیلد `ladderRollup` در خروجی JSON |

### پله‌ها (rungs) — فقط در رخدادهای تغییر ثبت می‌شوند (نه هر تیک)

`open` (ورود) → `arm` (سود بالغ شد و بریک‌ایون مجاز شد) → `be` (استاپ به ورود منتقل شد) → `trail` (ترلینگ استاپ را جابه‌جا کرد) → `guard` (قفل TF فعال شد) → `close` (بسته شد + دلیل).

هر پله: زمان، قیمت، استاپِ لحظه‌ای، آبِ سود، ATR. سقف ۱۶۰ پله به‌ازای هر معامله (پلهٔ ورود همیشه حفظ می‌شود)؛ فقط ۴۰ معاملهٔ آخر رکورد کامل نگه می‌دارند — قدیمی‌ترها فقط خلاصهٔ `ladder` (نردبانِ خودِ ذخیره‌سازی، تا storage سبک بماند).

### خلاصهٔ ladder روی هر معامله

`exitLayer` (کدام لایه بست: ۱=SL سخت … ۷=MaxHold)، `stopSource` (آخرین تنظیم‌کنندهٔ استاپ)، `mfePct`/`maePct` (بیشترین حرکت موافق/مخالف)، `beArmed`، `trailMoves`، `bars` (طول عمر به کندل).

> 🔧 فیکس ضمنی: برای معاملهٔ LONG فقط سقف سود (`highWater`) رهگیری می‌شد و `maePct` همیشه صفر بود — حالا هر دو آب برای هر دو جهت رهگیری می‌شوند.

### ممیزی زنده — حلقهٔ بسته با تست گوشی واقعی

```bash

node tools/stage-audit.mjs --live trading_export_hadi_123.json
```

خروجی: نردبان لایه‌های خروج از وقایع واقعی، ضریب برداشت از اوج، خروج‌های تقریباً بریک‌ایون، برنده→ضرر، خوشهٔ ماهانهٔ ضرر و نمونهٔ پله‌های آخرین معامله — همان کالبدشکافی ممیزی، این‌بار روی دیتای خود شما.
